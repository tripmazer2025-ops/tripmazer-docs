Trip story writes the trip up: a title, a short intro, one section per day with its photos placed, and a closing line. You get the parts to lay out yourself and the whole story as Markdown.

## Step by step

<Steps>
  <Step title="Get a key">
    Follow the [quickstart](/api/quickstart): create a developer account in the [console](https://tripmazer.com/developers/console), then make a **Test** key and a **Live** key under **API keys**.
  </Step>
  <Step title="Gather the trip">
    The days and places you already hold, up to 12 photo links, and anything the traveller told you. Ask for their OK to publish it.
  </Step>
  <Step title="Send the job">
    `POST /v1/jobs` with `kind: "trip_story"` and the input below. Start with the test key: it's free and answers at once with a sample.
  </Step>
  <Step title="Read the story">
    It takes seconds: add `?wait=55` to get it in the same response, or use a [webhook](/api/webhooks). You're charged only when it finishes.
  </Step>
  <Step title="Check it and publish">
    Read the story, then post `markdown` as it is or lay out `title`, `intro`, `days` and `closing` yourself. A story keeps your photo links, so keep those files online.
  </Step>
</Steps>

You can also run it from the console's **Playground**, where you fill in the request and press a button, or from an AI agent with the [MCP server](/api/mcp) (`trip_story`).

## Example

```bash
curl -X POST "$BASE/v1/jobs?wait=55" \
  -H "Authorization: Bearer $TRIPMAZER_KEY" -H "Content-Type: application/json" \
  -d '{ "kind": "trip_story", "input": {
        "destination": "Colombo",
        "days": [
          { "day": 1, "title": "Fort and the seafront", "stops": ["Old Dutch Hospital", "Pettah Market", "Galle Face Green"] },
          { "day": 2, "stops": [{ "name": "Gangaramaya Temple", "notes": "rain after lunch" }, "Barefoot Cafe"] } ],
        "photos": [ { "url": "https://example.com/galle-face.jpg", "day": 1, "caption": "Sunset" } ],
        "notes": [ "Kottu at midnight was the best thing I ate" ],
        "length": "short" } }'
```

| Input | |
| --- | --- |
| `destination` | Where the trip was |
| `days` | 1 to 30 days: `day`, optional `date` and `title`, and `stops` (names, or `{ name, time, notes }`) |
| `photos` | Optional, up to 12: a public `https` `url`, and optional `caption` and `day` |
| `notes` | Optional, up to 20: the traveller's own words; the story quotes or paraphrases them |
| `voice` | `first_person` (default, the traveller telling it) or `third_person` with `traveller_name` |
| `length` | `short`, `medium` (default) or `long` |
| `language` | Optional; English by default |

The result:

```json
{
  "title": "Two Days in Colombo",
  "intro": "…",
  "days": [ { "day": 1, "heading": "Fort and Markets", "text": "…", "photos": [1] } ],
  "closing": "…",
  "markdown": "# Two Days in Colombo\n\n…",
  "words": 193,
  "photos": [ { "index": 1, "url": "https://…", "scene": "A wide coastal view of a grassy promenade by the sea." } ],
  "language": "English"
}
```

## What it keeps to

- **Only what you sent.** Places, food and events come from the plan, the photos and the traveller's notes. The writer is told never to add a place, meal, person, incident, feeling or consequence, and to keep a thin day short. It is still written by a model, so read it before you publish it.
- **People.** It names someone only when the notes name them, and never describes anyone's looks; photo descriptions are of the setting.
- **Photos.** `scene` is `null` when we couldn't open the photo. The story still places it, so check the link.

<Tip>A test key returns a sample story shaped like the real one.</Tip>
